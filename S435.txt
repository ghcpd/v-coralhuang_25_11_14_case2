## 🔧 What I changed and why

- Issue: Application context misuse in background thread:
  - Fix: Pass the real app object into the async function (`current_app._get_current_object()`) and call `with app.app_context():` inside the thread before using `db` or `mail`.
  - Benefit: The thread no longer relies on the main thread’s context and gets its own valid app context.

- Issue: Background thread performed DB writes after tests teardown, causing flaky errors:
  - Fix: Tests either run synchronously or join the background thread before teardown, and the async function uses a fresh `app.app_context()`, so the DB session is valid in the thread.
  - Benefit: Deterministic test results and no race condition with teardown.

- Issue: Test environment not isolated/flaky:
  - Fix: Config using a file-based SQLite DB to avoid in-memory connection limitations across threads; tests set the application to synchronous sending by default for deterministic behavior.
